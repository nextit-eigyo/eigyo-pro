# 🔒 EIGYO PRO セキュリティ設定（Firebase）

Firebaseから「安全でないルールがあります」という警告メールが来た場合の対処。
**データを壊さずに**「URLを知る第三者の読み書き」を遮断します。

---

## なぜ安全に締められるのか

アプリ側は既に対応済みです:

- 匿名認証は**廃止済み**（誰でも通過できる穴を塞いである）
- **メール＋パスワード認証のみ**
- アプリからの**新規アカウント登録なし**（管理者がコンソールで作成）
- 会社全体で1つの共有データを全営業が読み書きする設計

→ ルールを `auth != null`（ログイン済みのみ）に締めても、**既存の同期は壊れません**。

### ℹ️ APIキーがHTMLに書いてあるのは正常です

FirebaseのAPIキーは「秘密」ではなく、公開されて問題ありません。
セキュリティは**APIキーを隠すこと**ではなく、**ルール＋認証**で守ります。
今回の対策（ルール厳格化）がまさにその守りです。

---

## 📱 スマホからの適用手順（5分）

1. ブラウザで **Firebaseコンソール** を開く → https://console.firebase.google.com/
2. プロジェクト **Eigyo-Pro** を選ぶ
3. 左メニュー **構築 → Realtime Database**
4. 上部タブ **「ルール」** をタップ
5. 表示されているルールを**全部消して**、下記を貼り付け:

   ```json
   {
     "rules": {
       ".read": "auth != null",
       ".write": "auth != null"
     }
   }
   ```

6. **「公開」** ボタンを押す（これで即反映）

適用後、アプリを開いて **ログイン → いつも通り数字が表示されるか** を確認してください。
（ログイン済みなら今まで通り動きます。）

---

## さらに強固にしたい場合（任意・なりすまし登録の封鎖）

公開APIキーで攻撃者が勝手にアカウントを作っても弾きたい場合は、
`database.rules.json` 内のコメント「【さらに強固にしたい場合】」を参照。
UID許可リスト方式に切り替えます。**全営業のUID登録を確認してから**実施してください
（入れ忘れると全員アクセス不可＝同期停止になります。データ自体は消えません）。

---

## 元に戻したい場合

ルールタブで以前の内容に戻して「公開」すれば即座に元通りです。
ルール変更は**データには一切触れません**（読み書きの許可条件を変えるだけ）。
